01 · Primeros pasos

Instalar y abrir el juego

Windows

  1. Descarga el instalador x64 desde el release oficial.
  2. Ejecuta el setup y elige la carpeta de instalación.
  3. Abre Neostellar desde el acceso directo o desde el menú Inicio.

El instalador actual no tiene firma PFX configurada. Comprueba el SHA-256 publicado antes de ejecutarlo.

Linux x86_64

  1. Descarga el paquete .tar.gz.
  2. Extrae la carpeta en un directorio de tu usuario.
  3. Desde esa carpeta ejecuta ./neostellar.

No uses sudo para iniciar el juego. Si el archivo no tiene permiso, aplica permiso de ejecución a ese binario.

02 · Juego online

Multijugador y modo global

El cliente debe usar la misma versión que el servidor. Actualmente es 2.1.47. El modo global entra directamente al mundo compartido y no necesita una sala intermedia.

  • Actualiza antes de entrar si el servidor rechaza tu versión.
  • Desactiva los mods locales para usar el multijugador oficial.
  • Consulta el estado del servidor si no puedes conectar.

Actualizaciones e integridad

04 · Creadores

Crear un mod Lua

Crea una carpeta dentro de mods/ con un manifest.json y un main.lua. Actualmente el cliente no incluye mods oficiales; esta estructura queda lista para los primeros mods de la comunidad:

{
  "id": "mi-primer-mod",
  "name": "Mi primer mod",
  "version": "1.0.0",
  "api_version": 2,
  "author": "Tu nombre",
  "description": "Contenido de ejemplo",
  "entry": "main.lua",
  "depends": [],
  "load_after": [],
  "load_before": [],
  "environment": "client"
}

El runtime ofrece eventos como init, update, draw, enemy_destroyed, wave_started, kill_boss_event y solo_sector_event.

La API permite consultar entidades, crear enemigos y drops, mover la nave, ajustar salud y fuel, dar puntuación, cambiar oleadas, reproducir sonidos y crear HUD. Los callbacks tienen límites de tiempo, instrucciones y entidades por frame.

Por seguridad, un mod no puede ejecutar procesos de Windows, leer credenciales, acceder a archivos privados, usar Python ni abrir sockets directos. Si un mod falla, se desactiva ese mod y el error queda registrado.

Consulta la guía completa incluida en la carpeta mods/ del cliente.

Una sola API estable

El cargador sigue el modelo conceptual de Minecraft Java, sin copiar su código: todos los mods usan únicamente la API 2, cada mod tiene un ID propio, se carga en un orden estable y puede declarar dependencias. Un manifest con otra versión se marca como incompatible.

function on_register()
  neostellar.registry.register("enemy", "plasma_raider", {
    base_type = "raider",
    damage = 5
  })
end

neostellar.events.register("update", function(data)
  -- lógica del mod
end)

El ciclo de vida es pre_init → register → post_init → init y termina con shutdown. Los registros usan namespaces como mi-primer-mod:plasma_raider y admiten enemy, drop, weapon, ability, minigame y hud. Puedes consultar contenido con neostellar.registry.list(tipo) o neostellar.registry.get(tipo, id).

Por seguridad, un mod no puede ejecutar procesos de Windows, leer credenciales, acceder a archivos privados, usar Python ni abrir sockets directos. Si un mod falla, se desactiva ese mod y el error queda registrado.

Consulta también la guía incluida en la carpeta mods/ del cliente para ver límites, skins y el canal de red propio del mod.

05 · Ayuda

Problemas comunes

No abre el juego

Descarga otra vez el paquete correcto, verifica el SHA-256 y revisa la carpeta logs/. En Linux confirma que estás usando el binario x86_64.

No puedo entrar online

Confirma que tienes la versión 2.1.47, que el servidor está disponible y que no hay mods oficiales activos bloqueando la conexión.
